Implantação do Sistema

Este guia pressupõe que estamos implantando o sistema em uma máquina base (Servidor VM ou Físico) que rode o sistema operacional Windows Server ou Windows 10/11 Pro disponível na rede local corporativa.

1 Pré-Requisitos na Máquina Host

  • Node.js: Versão 20 LTS ou superior. Faça o download do instalador clássico padrão no site oficial.
  • Git (Recomendado): Para baixar/clonar o código de forma rápida e puxar atualizações futuras com segurança via versionamento.
  • PostgreSQL: Baixe a versão Desktop standard ou via Docker. Grave a senha do superusuário postgres durante a instalação inicial e porta 5432.

2 Preparação da Rede

Atenção: Endereço IP Fixo

Sendo na intranet, sua máquina deve ter um IP estilo 192.168.X.Y. Comunique à TI/Infraestrutura para reservar este IP no DHCP! Se o roteador reatribuir o IP em um reinício, as máquinas de produção das Linhas vão perder acesso subitamente ao Dashboard.

3 Passo a Passo: Backend

1. Vá até a pasta backend pelo console e crie/configure o arquivo .env com seus parâmetros de subida do Banco e a porta: 

# .env File
DATABASE_URL="postgresql://postgres:SuaSenhaAqui@localhost:5432/aoi_db?schema=public"
PORT=3001
CORS_ORIGIN=http://192.168.X.Y:3000   // Substitua "X.Y" pelo IP Fixo do Host
NODE_ENV=production
JWT_SECRET="senha_forte_seguranca_jwt"

2. No Powershell da pasta backend como Administrador, rode a injeção do schema no postgres vazio: 

npm install
npx prisma generate
npx prisma db push

4 Passo a Passo: Frontend (Next.js)

1. Acesse a pasta nextjs-frontend e rode o Build de produção.

npm install
npm run build

Isto transformará o React pesado em HTML pré-renderizado estático super veloz (SSG + SSR).

2. Ao Finalizar o Build:

npm run start

O sistema subirá na Porta :3000.

5 PM2: O Segredo da Estabilidade

Você não deve deixar popups de prompt pretos abertos rodando o sistema manualmente. Um esbarrão, ou um Windows Update reiniciando à noite, e sua fábrica fica às cegas.

  1. Instale o gerenciador de processos globalmente (CMD Adm): npm install -g pm2
  2. Na pasta Backend levante o serviço isolado: pm2 start server.js --name "Aoi_Backend"
  3. Na pasta Frontend levante em paralelo: pm2 start npm --name "Aoi_Frontend" -- run start
  4. Tranque as configurações atuando o comando: pm2 save
  5. (Especial Windows): Execute npm install -g pm2-windows-startup e siga os passos dados no console. Com isso, caso caia a força na empresa, o PM2 irá subir tudo sozinho do zero sem o admin precisar sequer colocar a senha do Windows após ligar o PC.

Database Contingency (PostgreSQL)

Por migrarmos de um arquivo de teste isolado para um Banco de Dados Profissional (PostgreSQL), extrair cópias passa a exigir o sistema pg_dump. Abaixo os passos de rotina para blindagem contra Ransomware.

1 Regra Básica 3-2-1

3 Cópias

Sempre tenha 1 original e faça mais 2 backups contínuos.

2 Mídias

Salve uma na máquina, e a outra em HD/Nuvem Network/Drive.

1 Offsite

Isolação externa física (Nuvem ou Prédio Secundário).

2 Método de Extração Rápida (Manual)

Se for realizar uma manutenção de risco num feriado, extraia a base usando prompt via pg_dump: 

pg_dump -U postgres -F t aoi_db > "C:\Meus_Backups\backup_aoi.tar"

A flag -F t empacota silenciosamente a base. Utilize .sql no lugar de .tar se preferir texto corrido para debug puro.

3 Automação Diária (Powershell Silencioso)

Crie um arquivo fazer_backup_diario.ps1. Vá no "Agendador de Tarefas" do Windows e crie uma tarefa que dispare esse Script à Meia-Noite de cada dia. Desta forma você colapsará com zero surpresas de meses sem salvar. 

$DataDeHoje = Get-Date -Format "yyyy-MM-dd_HH-mm"
$DiretorioDestino = "C:\Backups_Sistemas\AOI\"  # E aponte pro GoogleDrive/OneDrive Synced
$NomeDoFile = "AOI_DB_$DataDeHoje.backup"
$CaminhoCompleto = Join-Path -Path $DiretorioDestino -ChildPath $NomeDoFile

# O PgPass injeta a senha invisível sem precisar pedir prompt humano
$env:PGPASSWORD="SUA_SENHA_AQUI"

Write-Host "Iniciando Dump das OMs do AOI Database..."
# Referencie o caminho nativo de instalação do PostgreSQL \bin
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U postgres -F c -b -v -f $CaminhoCompleto aoi_db

Write-Host "Base Backup efetuada com sucesso!"

4 Restaurando o Banco num Dia Ruim

Num evento que a base quebre ou máquina física queime: crie uma base nova aoi_db no postgres de uma maquina nova usando a UI (pgAdmin ou DBeaver).

Em seguida, rode magicamente via CMD o arquivo .backup extraído pela automação para recompor tudo que existia na tela naquele momento sem perder relacionamentos: 

pg_restore -U postgres -d aoi_db -v "D:\Backups\AOI_DB_2026-05-18_01-00.backup"

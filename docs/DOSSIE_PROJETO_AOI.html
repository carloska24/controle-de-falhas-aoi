SEC.01

Objetivo e Escopo do Sistema

O sistema de Controle de Falhas AOI é uma plataforma corporativa desenvolvida para a CADService Produtos Eletrônicos com o objetivo de gerenciar e rastrear a qualidade dos componentes e placas nas linhas de montagem de tecnologia de montagem em superfície (SMD/SMT).

A aplicação atende de forma integrada 5 perfis operacionais principais (RBAC):

OPERADOR
⚡
Operador de Produção
Lançamento imediato de defeitos encontrados durante a inspeção AOI e controle preciso do timer de Ordem de Manufatura (OM).
QUALIDADE
📊
Gestão da Qualidade
Acompanhamento de métricas estatísticas em tempo real, cálculo automatizado de DPMO, nível Sigma e Pareto de defeitos.
REPARO
🔧
Técnico de Reparo
Fila de placas com falhas para análise, retrabalho, alteração de status e registro de soluções aplicadas.
ALMOXARIFADO
📦
Almoxarifado
Gestão de requisições de componentes via Kanban interativo (pendente → separando → entregue) com alertas sonoros.
SEC.02

Arquitetura e Organização

🖥️ Frontend (Next.js 16)
  • frontend/app/: Páginas e rotas (App Router).
  • frontend/components/: UI e componentes de negócio.
  • frontend/lib/api.ts: Cliente HTTP com credenciais ativas.
  • Dashboards Chart.js e relatórios em PDF com jsPDF.
⚙️ Backend (Node.js Express)
  • backend/src/routes/: Definição modular de rotas.
  • backend/src/controllers/: Regras de negócio.
  • backend/src/middleware/: Autenticação JWT e logger.
  • backend/prisma/schema.prisma: Schemas do PostgreSQL.
🗄️ Persistência de Dados
  • Tabelas principais: users, registros, requisicoes.
  • Tabelas de OM: oms_ativas, oms_pausadas, oms_finalizadas.
  • Mapeamento de banco relacional com Prisma ORM.

SEC.04

Fluxos Principais do Negócio

1. Operação de Produção
Login → Iniciar Ordem de Manufatura (OM) → Lançar registros de defeitos (com serial, PN e designador) → Pausar/Retomar timer → Finalizar OM.
2. Fluxo de Reparo
Filtrar backlog de placas com defeito → Analisar componente indicado → Efetuar retrabalho → Atualizar status para reparado ou sucata.
3. Atendimento de Almoxarifado
Receber solicitação de insumos → Mover para status separando → Separar componentes por PN → Concluir entrega (status entregue).
4. Análise de Qualidade
Filtrar períodos ou OMs → Analisar curva de Pareto → Avaliar indicador DPMO e nível Sigma → Exportar relatório gerencial para tomada de decisão.
SEC.05

Mapa Resumido da API REST

Domínio Prefixo Métodos Descrição das Operações
Autenticação /api/auth POST GET Login (define cookie JWT), Logout (limpa cookie) e consulta da sessão (/me).
Usuários /api/users GET POST PUT DEL Gestão completa de usuários e perfis (acesso exclusivo admin).
Registros /api/registros GET POST PUT DEL CRUD de defeitos, inserção em lote (batch) e atualização de status em lote.
Ordem Manufatura /api/om POST PUT GET Iniciar, pausar, retomar, finalizar OM e consultar tempos/histórico.
Requisições /api/requisicoes GET POST PUT DEL Criação de requisições de insumos, atualização de quantidades e entregas.
Debug / Demo /api/debug GET POST Geração e limpeza de dados demonstrativos e rota de seed em ambiente seguro.
SEC.06

Diagnóstico de Riscos e Status de Resolução

RESOLVIDO
Proteção de Rotas de OM: Todas as rotas de controle de OM possuem middleware de autenticação (authenticateToken) e autorização por perfil.
RESOLVIDO
Endpoints Sensíveis Protegidos: Endpoints como /api/relatorio-falhas e /api/oms/finalizadas foram devidamente trancados para perfis autorizados.
RESOLVIDO
Sanitização de Rotas de Debug: Rotas em /api/debug exigem verificação de chave de ambiente (DEV_SEED_KEY) ou perfil administrador.
RESOLVIDO
Documentação e Deploy Sincronizados: Projeto 100% atualizado para refletir o frontend Next.js na Vercel e o backend Express no Render.
SEC.07

Plano de Evolução e Roadmap

FASE P0 · CONCLUÍDA Segurança, Estabilidade & Deploy CI/CD
  • ✅ Proteção total de rotas com JWT HttpOnly e middleware RBAC por perfil.
  • ✅ Inclusão de container PostgreSQL e migrations automáticas no GitHub Actions CI.
  • ✅ Separação clara de ambiente: Frontend na Vercel e Backend no Render.
FASE P1 · EM ANDAMENTO Qualidade Operacional & Experiência do Usuário
  • ✅ Implementação de Kanban interativo com drag-and-drop no Almoxarifado e Reparo.
  • ✅ Atualizações otimistas com rollback automático em caso de falha de conexão.
  • ⏳ Polimento dos atalhos globais de teclado (ex: Space para pausar OM, Ctrl+S para salvar).
FASE P2 · FUTURO Evolução Arquitetural & Observabilidade
  • 🔹 Implementação de mensageria em tempo real (WebSockets / Socket.io) para aviso de novas falhas na tela de reparo.
  • 🔹 Integração direta com leitores de código de barras / QR Code via câmera do tablet do operador.
  • 🔹 Estruturação de logs centralizados (Logtail / Datadog) para monitoramento proativo de erros no backend.
